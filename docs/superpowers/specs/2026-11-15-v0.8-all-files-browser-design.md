# v0.8 全部文件访问与内置文件夹浏览器设计

- 日期：2026-11-15
- 状态：已实现，v0.8.0 已发布（2026-11-15）
- 基线：v0.7.0（`feat/v0.7.0`）
- 分支：`feat/v0.8.0`

## 背景

系统 SAF 选择器不允许选择内置存储根目录、部分普通目录，用户在 v0.7 验收时遇到「有的文件夹无法选择」。目标是用可选的「全部文件访问」权限 + 应用内文件夹浏览器解决普通共享目录；`Android/data` / `Android/obb` 仍属于系统限制目录，留给后续 Shizuku 方案。

## 目标

1. Android 11+ 可申请 `MANAGE_EXTERNAL_STORAGE`，在系统设置里手动授权。
2. 授权后，应用内浏览器可从内置存储根目录逐级进入普通文件夹，并扫描其中的图片。
3. 未授权时继续使用现有 SAF 扫描，不强制权限。
4. 默认隐私立场不变：不申请网络权限，不上传文件；全部文件访问是显式可选项。

## 非目标

- 不接入 Shizuku；`Android/data` / `Android/obb` 仍不可选。
- 不添加 `READ/WRITE_EXTERNAL_STORAGE` 或 Android 10 的 legacy 存储模式；该功能仅 Android 11+。
- 不改动 v0.6/v0.7 的分享、提取、打包流程。

## 行为

- 提取页新增「全部文件访问」卡片：
  - 未授权：说明 + 「去授权」按钮，打开 `Settings.ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION`。
  - 已授权：显示已授权 + 「浏览全部文件」按钮。
  - Android 10 及以下：提示需要 Android 11+。
- 内置浏览器：
  - 从 `Environment.getExternalStorageDirectory()` 开始，只列目录。
  - 支持进入子目录、上一级、选择当前文件夹。
  - 无法读取的目录显示错误，不崩溃。
- 选择文件夹后复用 v0.7 的扫描流程：递归找图片、`CarrierProbe` 只读头部、显示进度/取消、结果加入提取。

## 实现

- `FolderScanner.collectImageFiles(root: File, shouldContinue)`：纯 `File` 递归，JVM 可测。
- `FolderScanner.scanDirectory(root: File, ...)`：用 `FileInputStream` + `CarrierProbe`，返回 `ScanHit(uri = Uri.fromFile(file))`。
- `MainViewModel`：
  - `allFilesAccess: StateFlow<Boolean>`，`refreshAllFilesAccess()`，API 30+ 用 `Environment.isExternalStorageManager()`。
  - `scanFolder(uri)` 与 `scanDirectory(file)` 共用 `startScan` 的取消/错误/进度逻辑。
  - `addScanHitsToExtract` 直接用 `ScanHit` 的 name/size，不再对 file URI 做 `describe`。
- `FolderBrowserDialog` Compose 对话框，`LazyColumn` 列目录。
- Manifest 增加 `MANAGE_EXTERNAL_STORAGE`（`tools:ignore="ScopedStorage"`）。

## 测试

- JVM：`FolderScannerTest` 覆盖递归、扩展名过滤、取消。
- JVM：现有 `CarrierProbeTest` 覆盖文件探测核心。
- 真机：授权全部文件访问 → 浏览内置存储根/Download → 扫描一个含载体图的目录 → 加入提取。

## 已知限制

- `Android/data` / `Android/obb` 仍不可读；需要 Shizuku 或 root。
- 全部文件访问是敏感权限，用户需在系统设置手动打开；应用不主动申请运行时弹窗。
- 内置浏览器只列目录，不列文件；选择的是文件夹。
